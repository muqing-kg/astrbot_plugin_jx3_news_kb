# astrbot_plugin_jx3_news_kb

![logo](logo.png)

剑网3活动提醒插件。实时接收 JX3API 公告推送并入库，从公告里抽取活动与截止时间，按截止日期逐日推送到期提醒。附 WebUI 管理页。

## 功能

### 公告采集

- 实时推送：连 `wss://socket.nicemoe.cn/`，收到 action `2002`（官方资讯）后立刻按 url 落库（标题/类型/地址/日期），随后拉最新公告补正文——两步顺序固定，先保证不漏，再补内容。服务端"首次入库才推送"，重复帧按 url 吸收。
- 定时同步：默认每 `sync_interval_minutes`（360 分钟）拉一轮，只做兜底——补推送漏掉的公告与缺正文的记录。
- 每日全量核对：默认 03:00（`daily_full_pull_time`）拉 `daily_full_pull_limit` 条，做一次兜底核对与正文补齐；错过的时点不会跳过一整天，启动后或下一轮会立刻补做一次；补做失败会按同步间隔退避，不会反复打接口。
- 推送、定时同步、全量核对共用同一把入库锁，不会并发写同一条公告。
- 用完即删：公告抽取完成后只要没有待发提醒就立刻删除，连同其活动与提醒记录；每轮同步结束和每次提醒发出后各检查一次。仍在等提醒、或尚未抽取完成的公告会留着。删除留下的墓碑记录保留 60 天，过期后一并清掉。
- 未配置提醒目标（白名单为空）或关闭提醒推送时不做这个清理，避免刚装好插件就把公告删空。
- 因此公告列表平时只剩下还在等提醒的那几条；被删掉的公告若仍在接口最近 50 条里，每轮都会计入同步日志的 `skipped`，属正常现象，不是抓取失效。
- 公告内容变更时追加修订记录，不覆盖历史；推送先写下的空正文记录，补正文时原地更新，不额外产生修订。
- 彻底删除写入指纹墓碑，之后同一 url / 内容指纹的公告不会再被抓回来；已删除的条目也不会再生成提醒。
- 空正文保护：后一次抓取拿到空正文（接口缺 `content` 或清洗后为空）按本次抓取失败处理，保留库里原有正文与修订记录，不会被覆盖成空。
- 日期留空而不是填占位值：接口的 `date` 与 `inputtime` 都不可解析时，发布时间存空串，页面显示"—"，后续补正文拿到时间再写入；不会出现 1970 年的假日期。
- 推送通道的连接有 20 秒超时，握手黑洞会触发重连而不是把循环挂死。

### 活动抽取

公告正文靠模型读懂，模型不可用时用日期区间兜底：

- 模型优先：把正文纯文本（截 16000 字）交给 `llm_provider_id` 指定的提供商（留空用默认对话模型），要求返回活动 JSON；解析失败、调用异常、拿不到提供商都视为"本轮没有模型"。
- 正则兜底：从正文里匹配"`X月X日H:MM—X月X日H:MM（维护前/后）`"这类区间（省略时刻的"`9月20日—9月25日`"也认，按当日 00:00 起、23:59 止），年份按公告发布日期就近归属（跨年窗口落到前一年或后一年），写到"维护前/维护后"的按当日 07:00 结算。
- 兜底结果也走同一套过滤（`confidence<0.55`、无截止时间、测试服、折扣券等一并剔除），因此只会少提醒，不会乱提醒。
- `announcements.activity_extract_mode` 记录该公告由谁抽出：`llm` / `regex` / 空（未抽）。模型不可用时先用正则；正则也没认出来，同样记为已抽取（`regex`）——这类公告对提醒没有价值，会随清理一起删掉。正则结果不会被模型结果覆盖；模型恢复后，正文变动过的公告仍会重抽。
- 一轮最多处理 50 条（按"未抽过优先、发布时间倒序"），正文更新过的公告会重新抽；只收到推送还没补到正文的公告不占抽取名额，等正文到手再进队列。
- 同一条公告里多个时间窗各自成条，同名不同窗的会带上"（M月D日）"以示区分；同一批里同名的第二条覆盖第一条，不会留下两条永远不更新的重复行。
- 发送失败（平台掉线、目标群不可用）不算已提醒：状态仍为待发，下一轮扫描重试；超过 10 分钟宽限的旧槽位按"错过不补发"取消。


### 活动到期提醒

只提醒与玩家"待办"相关的到期事项：

- 游戏内活动：签到、任务、代币收集/兑换、奖励领取。
- 免费券和免费道具：校服拓印券、捏脸券、捏体型券等（按实际用途判断，不看名字里有没有"券"字）。
- 券/道具本身的消失时间，即使活动已结束也提醒。
- 有明确领取期的奖励：月卡奖励、活动奖励邮件、福利返还。

不提醒：测试服活动、线下活动、问卷、折扣券/优惠券/几折促销、处罚与维护公告、纯玩法调整、无明确截止时间的内容、已过期事项。

提醒规则：

- 逐日倒计时：`reminder_days_before`（0–7，默认 1）表示提前几天开始，每天在 `reminder_send_time` 推送一次、天数递减；消息带"剩余时间"行（如"剩余时间：3 天，该活动将于9月20日结束"）。
- 维护日规则：截止时间在周一或周四中午 12 点前的活动随维护结束，最后一条提醒改在前一晚 `reminder_evening_time`（默认 21:00，`reminder_evening_enabled` 开关、留空时间亦可关闭），文案为"明早 07:00"样式。
- 临期加推：截止前 `reminder_urgent_minutes` 分钟（默认 60，`reminder_urgent_enabled` 开关）推送最后提醒；若该时刻早于当天常规提醒则只发这条；维护日早截止的活动不发。
- 短窗口活动（不足 24 小时）不再特殊处理，统一走以上规则；已流逝的提醒时刻自动跳过，错过不补发。
- 同一目标同一天的多条提醒合并为一条消息发送；提醒按活动/道具区分措辞（"【XX 结束提醒】/【XX 到期提醒】"）。
- 发送目标使用白名单里的完整会话地址（`平台ID:GroupMessage:群号` 或 `平台ID:FriendMessage:用户号`）；纯群号/用户号无法定位会话，不作为提醒目标。
- 提醒内容包含活动名、待办事项、相关物品、说明、剩余时间与链接。

### WebUI 管理页

插件页挂在 AstrBot WebUI 内（插件详情页 → Pages），不另开端口和密码：

- 状态总览：公告/活动/待发提醒数量、推送与同步状态、最近一次同步结果、下次同步时间、最近 48 小时待发提醒。
- 公告管理：搜索、类型筛选、分页，查看正文、原始 JSON 和修订历史。
- 彻底删除：无弹窗确认——勾选确认后执行。删除公告正文、活动抽取、待发提醒与日志，并写入指纹墓碑防止补抓恢复。
- 到期提醒页：直接列出仍在进行中的活动（截止时间未到），可对每条活动一键彻底删除该提醒，无需确认。
- 手动操作：同步 1 条 / 同步 10 条 / 全量核对 50 条。走与后台同一把入库锁，不会与推送、定时同步并发处理同一批公告。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `api_base_url` | `https://www.jx3api.com` | JX3API 地址 |
| `news_records_path` | `/news/records` | 公告列表接口路径 |
| `api_token` | 空 | JX3API Token（可选） |
| `proxy` | 空 | 抓取与推送共用的代理，如 `http://127.0.0.1:7890`；公告源只接受国内 IP |
| `sync_interval_minutes` | 360 | 定时同步间隔（分钟） |
| `initial_fetch_limit` | 50 | 首次安装抓取条数 |
| `fetch_limit` | 10 | 常规同步每轮条数 |
| `catchup_fetch_limit` | 50 | 停机超过 36 小时恢复时的补抓条数 |
| `daily_full_pull_time` | `03:00` | 每日全量核对时间 |
| `daily_full_pull_limit` | 50 | 每日全量核对条数 |
| `socket_enabled` | true | 实时推送开关 |
| `socket_url` | `wss://socket.nicemoe.cn/` | 推送通道地址 |
| `socket_ping_seconds` | 30 | 推送心跳间隔（秒） |
| `timezone` | `Asia/Shanghai` | 时区，用于计算同步与提醒时间 |
| `whitelist_groups` | 空 | 提醒推送的群：`平台ID:GroupMessage:群号` |
| `whitelist_users` | 空 | 提醒推送的私聊：`平台ID:FriendMessage:用户号` |
| `llm_provider_id` | 空 | 活动抽取的 LLM 提供商，留空用默认 |
| `reminder_enabled` | true | 是否启用提醒 |
| `reminder_days_before` | 1 | 提前几天开始逐日倒计时提醒（0–7） |
| `reminder_send_time` | `10:00` | 每日倒计时提醒推送时间 |
| `reminder_evening_enabled` | true | 维护日前一晚提醒开关 |
| `reminder_evening_time` | `21:00` | 维护日前一晚推送时间（留空关闭） |
| `reminder_urgent_enabled` | true | 临期加推开关 |
| `reminder_urgent_minutes` | 60 | 截止前多少分钟加推（0 关闭） |

插件的取数接口只接受 1～50 条，三个抓取条数配置写出范围（写成 0、100 或空）时会自动夹到 1～50，不会让每轮同步都失败。

插件不做聊天命令，也不响应聊天消息。公告进入库后由后台任务抽取活动并排好提醒，到点直接推送到白名单会话。

## 部署

1. 将本目录放入 AstrBot 的插件目录（或通过插件市场安装）。
2. 在 WebUI 插件配置中填写 Token、白名单和提供商 ID。
3. 重载插件：首次安装会立即同步一批公告建库，并启动推送、同步、提醒三个后台任务。
4. 打开 WebUI → 插件 → 剑网3活动提醒 Page 管理数据。

同步日志自动保留 7 天，超期由同步任务清理。

## 开发

```bash
pip install -r requirements.txt
python -m pytest -q
```

代码结构：

- `core/` — 数据库、JX3API 客户端、推送客户端、正文清洗、入库修订、活动抽取（模型 + 日期区间兜底）、提醒调度。
- `web_api/` — Plugin Page 后端路由（框架无关，便于测试）。
- `pages/jx3-news/` — Plugin Page 前端。
- `main.py` — 插件主类：后台任务、入库锁、提醒分发、Web API 注册。
